## Why

Vidoc 现在只有免费积分（每日 30），没有任何收款能力：`plans.ts` 已经把「月付 ￥19.9 / 年付 ￥189」摆在首页和仪表盘上，但三个按钮点了都没有去处；`PointsService.grantPurchase(userId, points, orderId)` 的 `orderId` 参数自始至终没有来源。接入支付宝电脑网站支付，是让付费套餐从「展示」变成「可购买」的最小闭环。

支付宝提供的是**页面跳转式**收单：下单接口返回一段自动提交的 `<form>`，不是 JSON；同步跳转不可信，支付结果只能以异步通知或主动查询为准。这两点决定了订单必须先落库、以及必须有幂等的通知端点。

## What Changes

- **新增订单**：用户选定套餐后创建订单，得到全局唯一的商户订单号；同一笔订单重复下单不会在支付宝侧产生第二笔单据。
- **新增发起支付**：调用 `alipay.trade.page.pay`（产品码固定 `FAST_INSTANT_TRADE_PAY`），把返回的自提交表单交给浏览器，跳转到支付宝收银台。
- **新增异步通知端点**：接收支付宝 POST 通知，用支付宝公钥验签，核对 `app_id` / `out_trade_no` / `total_amount` 与本地订单一致，再按 `trade_status` 发放积分。该端点必须公开可访问（支付宝不带我们的登录令牌），且必须幂等 —— 支付宝会重复通知同一笔交易。
- **新增主动查询兜底**：调用 `alipay.trade.query` 确认交易状态，用于通知丢失或用户从收银台返回时对账。
- **积分发放**：月付一次付款发放 2000 订阅积分，当期 30 天；年付一次付款分 12 期、每期 3000 订阅积分，逐期到账而非一次性发放。
- **新增积分充值**（2026-09-26 追加）：`/dashboard/plans` 拆成「订阅 / 充值」两个区。充值卖的是**永久积分**（进 `PURCHASE` 桶、永不过期、可重复购买），与订阅的**限时积分**是两种商品：订阅按期滴灌、每期到期作废、生效期内不可再买；充值一次性到账、随时可买。单点定价上充值必须比订阅贵（订阅是打包价），档位越大越划算。
- **前端**：`/dashboard/plans` 用 `UTabs` 分「订阅 / 充值」两区，两区共用同一套下单与跳转支付宝的流程；`/dashboard/billing` 列出该用户的订单与状态。
- **明确不做**（本期范围外）：退款（`alipay.trade.refund`）、对账单下载、关闭交易（改用下单时的超时时间控制）、**自动续费**（电脑网站支付是单次付款，续费需另开「周期扣款」产品，本期不做）。

## Capabilities

### New Capabilities

- `payment`: 订单生命周期与支付宝电脑网站支付对接 —— 创建订单、发起支付、接收并验签异步通知、主动查询交易状态、把支付结果确定性地映射到订单状态。不包含退款与对账。

### Modified Capabilities

- `points`: 新增「订阅额度按期发放」的需求。现有 spec 只写了「月付积分 / 订阅按月发放 / 当期结束」，但没有定义**一次付款分多期到账**时的行为 —— 具体是年付一次付款 12 期、每期 3000 积分逐期到账，以及某一期到期时如何结转到下一期。这是支付接入才暴露出来的规格缺口。

## Impact

**后端**

- 新增 `entity/Order`（商户订单号、用户、套餐、金额、状态、支付宝交易号、期数进度、时间戳）与对应仓储/服务/控制器
- 新增支付宝 SDK 依赖 `com.alipay.sdk:alipay-sdk-java`；SDK 客户端在启动时初始化一次，字段走 `application.yml` / 环境变量
- `config/SaTokenConfigure`：异步通知路径必须加入放行名单，否则支付宝的匿名请求会被 401 拦掉
- `PointsService`：订阅发放要支持「分 12 期、逐期到账」，现有 `grantSubscription(points, expiresAt)` 的「覆盖上一期」语义需要与滴灌节奏对齐
- `entity/Plan`：从「只有订阅档」扩成**两种商品**（订阅 / 充值），加一个商品类型字段；充值档复用 `periodPoints` 表示「一次性到账的永久积分」，`periods = 1`、周期长度为 0
- `payment/OrderService`：下单的「订阅生效期内拒绝」只对**订阅类**套餐生效；确认支付时按商品类型分支（订阅 → `grantSubscription`，充值 → 早已存在的 `PointsService.grantPurchase` 接缝）
- `db/schema.sql`：新增 `orders` 表（新环境建库用）
- 配置项：APPID、应用私钥、支付宝公钥、网关地址、沙箱开关

**前端**

- `/dashboard/plans` 从单页套餐改成 `UTabs` 的「订阅 / 充值」两区；`/dashboard/billing` 从占位页变成真实订单列表
- 新增支付相关的 composable 与类型

**外部依赖 / 运维**

- 支付宝开放平台：创建网页应用、RSA2 加签、填应用网关、提交上线审核（约 1 个工作日）、绑定商家账号、开通「电脑网站支付」
- 站点必须已是 HTTPS：`notifyUrl` / `returnUrl` 必须是公网可访问的 `https://vidocnote.com/...`
- 开发期用沙箱联调；**沙箱的电脑网站支付只支持余额支付**，验收必须走线上
