## 三步流程

Vidoc Note 不下载视频本体，只处理**字幕文本**：

1. **解析视频信息**：通过视频链接读取元数据——标题、UP 主、时长、封面。
2. **获取并解析字幕**：抓取该视频的字幕文本（人工上传的字幕或平台自动生成的字幕），并清洗成纯文本。
3. **生成 Markdown**：把字幕文本交给大语言模型，要求输出结论先行的结构化摘要，最后以 Markdown 呈现，便于阅读与复制。

因此，摘要的质量上限取决于两件事：**字幕的质量**和**字幕的信息量**。没有字幕就没有可归纳的内容。

## 能力边界

### 必须有字幕，暂不支持语音识别

生成摘要依赖视频自带的字幕。Vidoc Note 目前**不支持 ASR（自动语音识别）**，所以：

- 纯音乐、无对白、UP 主没有上传字幕且平台也没生成字幕的视频，无法生成摘要。
- 外语视频若只有外语字幕，摘要会以该字幕内容为准，语言可能与视频原声不同。

### 时长上限 3 小时

单条视频时长超过 **3 小时**会被直接拒绝，并且**不消耗积分**。原因很直接：长视频占用处理资源更久，而且 3 小时以上的字幕会接近模型单次输入的处理上限。

### 超长字幕会被截断

字幕文本超过处理上限（约 8 万字符）时，超出部分会被截掉，并在摘要中标注「**内容已截断**」。这类摘要只覆盖视频靠前的部分内容。

同理，模型输出达到长度上限时，已生成的内容照常交付，并在摘要中标注截断，不会整篇作废。

### 摘要由 AI 生成，可能有误

大语言模型可能误读字幕、把玩笑当事实、或过度概括。Vidoc Note 的定位是**帮你快速定位重点**，不是替代原视频。涉及数据、结论、引用的内容，请回到视频核对。

## 一个典型的时间预期

| 视频时长 | 大致等待时间 |
| --- | --- |
| 5 分钟以内 | 十几秒 |
| 10～30 分钟 | 二十秒到一分钟 |
| 1 小时以上 | 一分钟以上 |

具体还取决于排队情况：当同时生成的任务较多时，请求会排队而不是直接失败。
